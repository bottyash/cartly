01

Introduction & Architecture

Cartly is an agentic AI system that autonomously triages, evaluates, and resolves customer refund tickets without human intervention for straightforward cases. It exposes a RESTful HTTP API built with FastAPI, backed by a multi-agent orchestration pipeline powered by LLaMA-3.2-3B via OpenRouter.

Pipeline Overview

// Orchestration Pipeline
Customer Request (POST /tickets)
   |
   v
+-------------------------------------------------------------+
|                Orchestrator Agent                 |
|  1. Hard-trigger check (legal/fraud keywords)          |
|  2. Triage LLM -- intent + risk_tier + category        |
|  3. Threshold gate: amount > Rs500? --> ESCALATE       | <- deterministic
|  4. Refund Agent: DB lookup --> Policy KB --> LLM reasoning|
|  5. Safety Critic: re-fetch KB --> faithfulness score   |
|  6. Verdict --> ResolutionResponse + full trace        |
+-------------------------------------------------------------+
          |                               |
   LLM Calls                    Every step
 (OpenRouter)                --> TKT-*.json log

Tickets — Submit & Query

POST /tickets tickets

Submit a customer support ticket. The orchestrator runs the full multi-agent pipeline and returns an autonomous resolution or escalation.

Request Body

{
  "raw_ticket": "My order #1042 arrived damaged, I'd like a Rs350 refund",
  "order_id":   "1042",
  "claimed_amount": 350.0,
  "buyer_id":  "buyer_42",
  "channel":   "web"
}

Response (200 OK)

{
  "ticket_id": "TKT-3A7F8B12",
  "status": "resolved",
  "resolution": {
    "eligible": true,
    "action_taken": "refund_issued",
    "reason": "Product arrived damaged; eligible under POL-001.",
    "source_refs": ["POL-001"],
    "transaction_ref": "TXN-ABCD1234",
    "faithfulness_score": 0.92
  },
  "handoff_brief": null,
  "trace": [ /* ObsStep array */ ],
  "total_latency_ms": 1243.7,
  "total_cost_tokens": 1872
}

Status Codes

200 OK
Resolved or escalated
422 Unprocessable
Validation error
503 Unavailable
DB down, auto-escalated
POST /tickets/generic tickets

Submit a product/policy question without an order ID.

Request Body

{ "query": "Is the SoundMax Pro Bluetooth Speaker returnable?" }

Status Codes

200 OK
ResolutionResponse returned
422 Unprocessable
Missing "query" field
GET /tickets tickets · admin

List recent tickets (last 50) with status summary. Requires admin token.

Response (200 OK)

{
  "tickets": [
    { "ticket_id": "TKT-3A7F8B12", "status": "resolved", "steps": 6 }
  ]
}

Live Chat — Human Agent

ℹ️
Live chat endpoints support real-time handoff to a human agent. Users open a ticket, admins pick it up, and both sides exchange messages. The ticket auto-activates when an admin sends the first message.
POST /live/connect live

Open a live-chat ticket requesting a human agent. Use "WALK_IN" as order_id to skip order validation.

Request Body — LiveConnectRequest

FieldTypeNotes
order_idstring (max 20)Must exist in DB or be "WALK_IN" required
buyer_namestringCustomer's name required
product_namestringProduct involved optional
issue_summarystringBrief description optional

Status Codes

200 OK
Ticket created
404 Not Found
Order not found
GET /live/tickets live · admin

Admin: list all live tickets, optionally filtered by status. Requires admin token.

Query Parameters

ParameterTypeDescription

Get a single live ticket with full message history. Polled by both user and admin.

Status Codes

404 Not Found
Ticket not found

Append a message to a live ticket. Admin's first message auto-activates the ticket.

Request Body — LiveMessageRequest

Observability & Logs

GET /health meta

Liveness and database readiness probe. Returns 200 if healthy, 503 if DB is unavailable.

Response (200 OK)

{ "status": "ok", "db": "ok", "service": "cartly-api", "version": "1.0.0" }
GET /logs/{ticket_id} observability

Retrieve the full JSONL event trace for a ticket. Each event = one pipeline step with latency, token cost, decision, and metadata.

Response (200 OK)

{
  "ticket_id": "TKT-3A7F8B12",
  "events": [
    {
      "step": "triage",
      "ts": "2026-07-21T13:00:01.234Z",
      "latency_ms": 312.4,
      "cost_tokens": 480,
      "decision": "refund_request | low | damaged_goods",
      "metadata": { "intent": "refund_request", "risk_tier": "low" }
    }
  ]
}

Pipeline Steps

Step NameDescription
hard_trigger_checkLegal threats and fraud keyword detection
triageLLM intent classification + risk tier
threshold_gateDeterministic Rs500 escalation check
refund_agent_order_lookupDatabase order fetch
refund_agent_llmLLM refund reasoning with policy KB
safety_criticFaithfulness validation of refund decision
orchestrator_verdictFinal resolved/escalated decision

Error Reference

All error responses follow FastAPI's default structure:

{ "detail": "Human-readable error message" }

DB errors additionally include an escalated: true flag:

{ "detail": "The database is temporarily unavailable...", "escalated": true }
CodeNameWhen It Occurs
200OKRequest succeeded
401UnauthorizedX-Buyer-Name header missing on /orders/{id}
403ForbiddenInvalid/missing admin token, or order ownership mismatch
404Not FoundOrder, product, ticket, or log file not found
409ConflictSending message to an already-resolved live ticket
422Unprocessable EntityPydantic validation failure (missing fields, out-of-range)
503Service UnavailableDatabase connection failure; ticket auto-escalated to human
